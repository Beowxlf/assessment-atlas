# Native web workbench — 0.2.0

Start Atlas, create/select a workspace and open **Web workbench**. Set the owned start URL, path boundary, testing position, evidence context, excluded paths, limits and authority checkbox. Additional origins must be explicit owned URL scopes (up to four); add a login/API origin only when authorized. Normal upstream hostname/CA validation stays enabled. An optional **public** CA PEM field supports an owned private lab without disabling TLS.

Imports remain inert. Nothing imported starts a crawl, proxy, payload test or browser. Live tools are deliberate separate actions, and source artifacts distinguish `offline` from `native live` intake. No endpoint agent is installed. A discovered web path/parameter is not directory traversal, a physical link or validated exploitation.

## Setup

Python 3.12+ remains required. Crawling, request editing/comparison, selected-parameter tests and response checks use the standard library. HTTP/HTTPS interception requires **cryptography** in the Python used to launch Atlas: `python -m pip install -r requirements-web.txt`. The release is tested with cryptography 50.0.2; the allowed dependency range is not an exhaustive support matrix. The dependency is used, not copied into the ZIP; its licensing does not choose the project license.

The isolated browser requires Node.js, Playwright and Microsoft Edge. In an owner-controlled tools directory, install Node and use `npm install playwright`; set `ATLAS_PLAYWRIGHT_MODULE` to its Playwright module path and optionally `ATLAS_NODE` to the Node executable before starting Atlas. Existing Codex desktop bundled Node/Playwright is detected when available. The tested browser worker uses Playwright 1.62.1 and the installed Edge channel. No existing browser profile, system proxy, Burp setting or global certificate store is changed.

## Workflows

1. **Crawl & paths:** follow permitted links/resources with GET or enter up to 50 explicit paths. Forms are discovered but not submitted. Out-of-scope redirects/references are recorded/skipped, never followed automatically. Default limits: 40 requests, 60 seconds, depth two, 500 ms between requests. Hard bounds: 200 requests, 300 seconds, depth four, at least 250 ms delay. Up to two jobs may run concurrently.
2. **Edit, resend & compare:** enter an in-scope request URL, one of GET/HEAD/POST/PUT/PATCH/DELETE/OPTIONS, headers and UTF-8 body. Body limit is 16 KiB. Transport controls framing/Host/connection headers; duplicate/newline headers are rejected. Redirects are returned rather than automatically followed. Inspect a bounded raw response and compare two captures from the current process/session (500 difference-line limit). Saved evidence follows the metadata/redaction selection; credentials are not persisted for replay. State-changing methods are deliberate operator actions.
3. **Parameter tests:** uses the selected editor request, one named query or form parameter and one to twenty supplied payloads (512 characters each). Makes one baseline plus variants under common limits. Form variants use POST. Reflection/status differences remain tool-reported indicators, with baseline/digest references; they never prove browser execution or exploitability.
4. **Intercept:** start the scoped authenticated proxy on an unused loopback port (default 8877, distinct from Atlas). Use its transient `atlas`/password credentials in a separate test browser. HTTPS needs explicit trust of its **public** per-session CA in that separate profile, or use the Atlas-owned browser. Atlas does not install global trust. CA private key remains in memory; an OS-restricted temporary leaf key is removed immediately after SSLContext loads it. Enable interception, edit method/headers/body, then forward or drop. URL origin/path remains scoped; pending requests drop after 30 seconds. Stop the proxy when finished; do not reuse its CA as a general trust root. No CA private key is exported.
5. **Authenticated browser:** opens a fresh visible Atlas-owned Edge window through the authenticated proxy. It trusts only the specific ephemeral Atlas CA SPKI for this isolated process; there is no broad certificate-ignore mode, and upstream TLS still undergoes normal hostname/CA validation. Sign in and exercise application flows interactively; cookies stay in its fresh browser context and are discarded on close. Explicit origin/path routing plus the proxy enforce scope. Service workers and WebSockets are blocked. Downloads are not accepted. The browser/proxy stops at its configured request/time boundary; it is not an indefinite background collector.
6. **Scanner checks:** one GET of the start URL and the exact original response-check families in [Coverage](native-web-coverage.md). No automatic audit is triggered by crawl/import. Review and validate indicators separately. Advanced scanner families and competitor accuracy remain unfinished.

Use **Inspect collected map** to see logical devices/services, web origins, resources and parameters. Each observation preserves capture time, tool/parser version, source digest, position and basis. Matching names/addresses never silently merge identities. Repeated live requests have separate event IDs/time; a repeated identical envelope deduplicates, and conflicting content for one event ID is rejected. Link identities only with evidence and use undo to preserve history.

## Retention, limits and recovery

Metadata mode omits bodies, redacts sensitive headers and query values, and retains only selected header values. Optional body mode stores up to 8 KiB of best-effort redacted UTF-8 excerpts; review them because pattern matching cannot find every secret. URL paths and parameter names can themselves be sensitive. Transient editor/response buffers hold at most 20 exchanges per process. Raw originals are not stored; body digests identify captured bytes, with truncation/digest limits disclosed. Normal response read limit is 64 KiB; proxy forwarding limit is 2 MiB, while its retained excerpt remains 8 KiB. Binary responses can be forwarded, but binary request uploads, chunked requests and protocol upgrades are unsupported. These limits can exclude modern bundles or long bodies; no universal SPA reliability is claimed.

Stop controls retain completed captures; an in-flight bounded request may finish. Runs distinguish completed, partial, cancelled, failed, stopped and interrupted states. On restart, unfinished persisted jobs become interrupted and never resume automatically. Stop active jobs/proxies/browsers before deleting a workspace. JSON/HTML reports include run plans/outcomes; default exports withhold plans and evidence identifiers/free text. Original files, browser/device data and external downloads remain separately controlled.

Database schema is **2**. Opening a schema-1 database first creates an exact SQLite backup beside it (`*-before-schema2-<unique-id>.sqlite3`) and preserves existing workspace/evidence/history contents. New run metadata is additive. Older Atlas versions reject schema 2; to return to 0.1.1, stop Atlas, preserve the current data folder and restore the schema-1 backup into a separate folder. Do not overwrite later captures silently. Protect backup/data folders with OS account/disk controls; app encryption is still absent.

Development checks: `python -m unittest discover -s tests -v`; legacy browser workflow `node tests/ui.cjs`; native workflow `node tests/web-ui.cjs` against deliberately started owned fixture servers with `ATLAS_WEB_FIXTURE`, `ATLAS_WEB_TLS_FIXTURE`, `ATLAS_WEB_CA`, `ATLAS_UI_URL`, `ATLAS_UI_OUTPUT` and `ATLAS_PLAYWRIGHT_MODULE` set. Native UI tests use a real isolated Edge worker in headless mode; this test flag does not alter the visible user workflow. See [Verification](verification.md) and [security review](web-security.md).

Proxy transport limits also include sixteen concurrent connections, five-second TLS handshake and ten-second request-header/body reads. The isolated browser disables QUIC and non-proxied WebRTC UDP; this is a bounded HTTP browsing tool, not a general browser network sandbox.
