Web workbench

Collect deliberately. Every saved request, response, endpoint, parameter and check belongs to this workspace’s evidence.

Target and collection scope

Imports stay inert. These tools make real requests only after you set the scope. Crawling uses GET; forms are discovered without automatic submission.

Scan authentication

Use a protected session-check URL with a unique signed-in text marker. Atlas compares it with an anonymous response, verifies the session throughout a scan, and stops if it loses access. Sessions are held in memory for one hour; credentials are withheld from saved evidence and reports.

Build a username and password login

Preparing a sequence makes no network requests. Keep the session below, then start a scan to validate it. Login and session-check URLs must be in your exact scope.

Cookie / bearer headers and login sequence

Login steps can extract JSON paths, hidden fields or response headers into named {{token}} placeholders. Each URL must be explicitly in scope. Redirects require an explicit next step. MFA/SSO can be completed interactively, then use the isolated browser’s cookies.

Crawl links and discover paths

Outside-scope redirects are recorded and blocked. A returned path/status does not establish directory traversal, physical topology or a vulnerability.

Edit and resend a request

The editor and raw bounded response are transient. Headers/credentials are not saved for automatic replay. Enter authenticated values only in this local editor or the isolated browser.

Bounded tests of one selected parameter
Uses the request URL, method, headers and body from the editor. Makes one baseline request, then one request per supplied payload. It does not guess credentials or start a wider scan.
Reflection and status changes are indicators for review; they do not prove script execution or exploitation. Methods such as POST/DELETE can change application state.

  
Local HTTP and HTTPS interception
Start an authenticated loopback proxy for this exact scope. Forward requests unchanged or edit them live; drop unwanted requests. Pending requests fail closed after 30 seconds.
An ephemeral Atlas CA is generated in memory. Existing certificates, global trust, browser profiles and Burp settings are untouched. HTTPS requires the optional TLS library. Use the Atlas browser below, or deliberately configure a separate test browser with the displayed local proxy credentials and public CA.

  
Authenticated and JavaScript browsing
Open a fresh Atlas-owned Edge window through the scoped proxy. Sign in and exercise JavaScript flows yourself; requests, responses and parameters feed this workspace. Explicitly add any owned login/API origins before starting.
Requires Node.js, Playwright and Microsoft Edge. Cookies remain in the temporary browser context and are discarded when it closes. Service workers are blocked; scoped WebSockets are captured; cross-origin apps require explicit additional scope. This is interactive session coverage, not universal authentication automation.

Broader original audit families
Stateful and file tests use only the explicit canaries you supply. Callback tests require your active receiver. Findings retain their source and controls; the indicators do not establish unrestricted execution, disclosure or browser exploitability.
Explicit API requests and custom response checks
Each original check has bounded coverage. Reflection, error signatures and response comparisons require operator validation. A completed run is not a clean security verdict or full Burp Scanner parity.

  
Multi-position payload tests
Uses the request URL, headers, method and body from the editor, plus the selected scan session. All requests count against the shared limits.
Decoder and sample measurements
Decoded text is never executed. Sample distributions and duplicate counts do not establish cryptographic strength or predictability. These utility inputs/results are not saved.

  
WebSocket messages, editing and replay
Open a scoped ws:// or wss:// channel. Uses the selected transient session for an authenticated handshake. Text and binary/Base64 messages are bounded to 64 KiB. Incoming and sent messages feed assessment evidence; mark a message finding to add it directly to Findings.
